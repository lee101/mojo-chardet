# mojo-chardet

`mojo-chardet` is an experimental Mojo implementation of the compute-heavy
part of character-set detection. Its Python call signatures match the current
public `chardet` entry points, but its candidate registry and statistical model
are intentionally smaller. It validates and classifies bytes in native code,
then uses a Python policy layer to rank plausible encodings.

The project does not import or require upstream `chardet` at runtime. Upstream
`chardet` is a development dependency used by parity tests and benchmarks.

## Coverage

Tests cover these public interfaces and behaviors:

- `detect(...)` and `detect_all(...)`;
- `UniversalDetector.feed()`, `close()`, `reset()`, `done`, and `result`;
- `EncodingEra` and `LanguageFilter`, plus the canonical
  `mojo_chardet.detector.UniversalDetector` import;
- compatibility names, preferred-superset renaming, input size limits, empty
  input handling, include/exclude filtering, and invalid-option errors;
- top-choice parity for ASCII, strict UTF-8, UTF byte-order marks, BOM-less
  UTF-16/32, cp932, EUC-JP, GB18030, Big5, EUC-KR, Windows-1251, KOI8-R,
  ISO-8859-5, IBM866, Windows-1253, and Windows-1252 test corpora;
- ISO-2022-JP/KR and HZ escape-signature recognition.

This is not a drop-in implementation of the entire upstream detector.
Encodings outside the tested list may appear as heuristic candidates but are
not claimed as supported. In particular, the full upstream EBCDIC, Vietnamese,
Thai, Georgian, historical Mac/DOS, and language-model registries are absent.
`encoding_era`, `chunk_size`, and the streaming detector's `lang_filter` are
accepted for signature compatibility but do not change candidate selection.
Streaming buffers input up to `max_bytes`; it does not perform incremental
prober updates. Legacy confidence values are independently calibrated and are
not expected to reproduce upstream values.

## Install

From a checkout:

```bash
pixi install
pixi run build
pixi run test
```

The build task creates `dist/libmojo-chardet.so`. For a separately deployed
library, set `MOJO_CHARDET_LIB` to its absolute path.

## Usage

```python
import mojo_chardet as chardet

data = "これは日本語の文章です。".encode("shift_jis")
result = chardet.detect(data)
assert result["encoding"] == "cp932"
print(result["encoding"])
```

Run the example within the environment with `pixi run python`.

## How it works

One Mojo compilation unit performs the repeated byte work: a byte histogram,
byte/control/null statistics, strict UTF-8 validation, zero-position analysis
for UTF-16/32, and independent finite-state scans for the covered East Asian
multibyte families. Single-byte candidates are ranked from the native
histogram and a bounded language-bigram sample. Large scans use SIMD byte
classification with a scalar remainder. The finite-state validators remain
serial because each byte determines the position and state of the next step.

The Python wrapper calls one C ABI export through `ctypes`. Buffers cross the
ABI as integer addresses. Mojo reconstructs typed pointers and writes into
caller-owned, C-contiguous `int64` NumPy arrays. The wrapper checks the input
length, dtypes, layout, and native status, and keeps all buffer owners alive for
the call. The native function rejects null addresses and negative lengths,
allocates no per-call data buffers, and retains no pointers. Full input `bytes`
and `bytearray` objects remain zero-copy through the NumPy/FFI boundary.

There is no GPU path. Detection is dominated by byte classification, histogram
updates, and branch-heavy finite-state scans, all well below the roughly two
flops per byte needed to justify transfer and launch overhead. The benchmarked
CPU implementation is already more than 5x faster than upstream on every
workload, so neither GPU dispatch nor CPU thread-launch overhead is warranted.
